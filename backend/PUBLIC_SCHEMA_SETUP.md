# Public Schema Setup Guide

This guide will help you set up the tables in the **public schema** in your Supabase project.

## 1. Create Tables in Public Schema

In your Supabase dashboard, go to the SQL Editor and run these commands to create tables in the **public schema**:

### Inspection Table
```sql
CREATE TABLE public.inspection (
  id bigint generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  full_name text null,
  street_address text null,
  square_footage integer null,
  has_visible_mold boolean null,
  mold_locations text null,
  mold_images text[] null,
  has_water_damage boolean null,
  water_damage_locations text null,
  water_damage_images text[] null,
  thermostat_image text null,
  status text null,
  created_date timestamp without time zone null,
  updated_date timestamp without time zone null,
  created_by_id uuid null,
  email text null,
  is_sample boolean null,
  city text null,
  client_type text null,
  property_type text null,
  state text null,
  zip_code text null,
  constraint MoldInspection_pkey primary key (id)
);
```

### Samples Table
```sql
CREATE TABLE public.samples (
  id bigint generated always as identity not null,
  inspection_id bigint null,
  location text null,
  description text null,
  sample_image text null,
  created_at timestamp with time zone null default now(),
  constraint samples_pkey primary key (id),
  constraint samples_inspection_id_fkey foreign KEY (inspection_id) references public.inspection (id) on delete CASCADE
);
```

### User Profiles Table
```sql
CREATE TABLE public.user_profiles (
  id uuid not null,
  full_name text null,
  role text null default 'user'::text,
  created_at timestamp without time zone null default timezone ('utc'::text, now()),
  email text null,
  constraint user_profiles_pkey primary key (id)
);
```

## 2. Update Backend to Use Public Schema

After creating the tables in the public schema, the backend will automatically use them.

## 3. Run the Backend

## Important Notes

- **Schema**: All tables must be created in the **public schema**
- **Table Names**: Use `inspection`, `samples`, `user_profiles`
- **Foreign Keys**: Make sure foreign key references include the schema prefix
- **Permissions**: Ensure your Supabase anon key has access to the public schema

## Troubleshooting

If you get schema errors:
1. Make sure tables are created in the **public schema**
2. Check that your Supabase project is configured to use the public schema
3. Verify the table names match exactly: `inspection`, `samples`, `user_profiles`
